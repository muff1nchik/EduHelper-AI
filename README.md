# EduHelper AI

EduHelper AI — локальный образовательный Telegram-бот для работы с учебными материалами. Бот принимает документы, извлекает из них текст, сохраняет фрагменты в SQLite и отвечает на вопросы по активному материалу через локальную Ollama.

Проект не использует облачное хранение документов: база данных и загруженные файлы находятся на компьютере, где запущен бот.

## Возможности

- загрузка PDF, TXT, Markdown и DOCX;
- локальная обработка материалов через SQLite и Ollama;
- гибридный semantic + lexical retrieval по активному документу;
- ответы только на основе загруженных материалов;
- отображение источника ответа;
- Telegram Rich Messages для итоговых ответов и конспектов;
- отображение Markdown и LaTeX через `$...$` и `$$...$$`;
- автоматическая проверка и исправление некорректного Rich Markdown;
- защита от очевидных prompt injection-запросов;
- проверка ответов модели на возможные утечки внутренних инструкций и секретов;
- изоляция документов пользователей по Telegram `user_id`;
- блокировка повторного тяжёлого запроса одного пользователя;
- выбор активного документа;
- удаление одного материала или полная очистка материалов пользователя;
- конспект активного документа через `/summary`;
- интерактивная викторина по активному документу через `/quiz [N]`;
- быстрые встроенные ответы на вопросы о возможностях бота;
- поддержка уточняющих вопросов в рамках активного документа.

## Как это работает

```text
Telegram → файл → loader → нормализация → splitter → embeddings → SQLite
Telegram → вопрос → hybrid retrieval → Ollama → ответ
```

Основной сценарий:

1. Пользователь отправляет PDF, TXT, MD или DOCX.
2. Бот сохраняет файл в `data/uploads`.
3. Загрузчик извлекает текст.
4. Текст нормализуется и делится на фрагменты.
5. Для фрагментов создаются embeddings через `nomic-embed-text`.
6. Документ, фрагменты и embeddings атомарно сохраняются в SQLite.
7. Новый документ автоматически становится активным.
8. Вопрос пользователя ищется по активному документу.
9. В найденный контекст добавляются релевантные соседние фрагменты.
10. Ответ генерируется локальной моделью `qwen3:8b`.

## Безопасность и ограничения

- Вопросы пользователей и содержимое документов рассматриваются как
  недоверенные данные.
- Бот блокирует очевидные попытки раскрыть внутренние инструкции, токены,
  ключи, пароли и конфигурацию.
- Документы, активный материал и история уточняющих вопросов разделяются по
  Telegram `user_id`.
- Модель не получает прямого доступа к файлам, SQLite, `.env` или операционной
  системе.
- Ответы модели проверяются на возможные утечки внутренних инструкций и
  секретов перед отправкой пользователю.
- Абсолютная защита от всех вариантов prompt injection не гарантируется.
- Не помещайте секреты, токены, пароли и приватные ключи в загружаемые
  документы.
- Локальная Ollama может обрабатывать запросы медленно при нескольких
  пользователях или больших документах.

## Установка

Создайте виртуальное окружение и установите зависимости:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Создайте файл окружения:

```bash
cp .env.example .env
```

В `.env` укажите токен Telegram-бота:

```env
BOT_TOKEN=your_telegram_bot_token
```

Остальные настройки можно оставить по умолчанию или изменить при необходимости:

```env
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_CHAT_MODEL=qwen3:8b
OLLAMA_EMBEDDING_MODEL=nomic-embed-text
OLLAMA_TEMPERATURE=0.2
OLLAMA_NUM_CTX=4096
DATABASE_PATH=data/eduhelper.db
UPLOADS_DIR=data/uploads
CHUNK_SIZE=800
CHUNK_OVERLAP=150
TOP_K=4
MIN_SIMILARITY=0.35
```

## Ollama

Установите модели:

```bash
ollama pull qwen3:8b
ollama pull nomic-embed-text
```

Перед запуском бота Ollama должна быть запущена локально:

```bash
ollama serve
```

## Запуск

```bash
python main.py
```

После запуска откройте Telegram-бота и отправьте:

```text
/start
```

## Команды бота

| Команда | Назначение |
| --- | --- |
| `/start` | начать работу |
| `/help` | показать инструкцию |
| `/documents` | показать загруженные материалы |
| `/use ID` | выбрать активный материал |
| `/delete ID` | удалить материал |
| `/clear` | удалить все свои материалы |
| `/summary` | создать конспект активного материала |
| `/quiz [N]` | начать викторину по активному материалу |
| `/stopquiz` | остановить текущую викторину |

`/quiz` без числа создаёт 5 вопросов. Допустимое количество вопросов: от 1 до 10.

## Пример использования

1. Запустите Ollama.
2. Запустите проект командой `python main.py`.
3. Откройте Telegram-бота.
4. Отправьте PDF, TXT, MD или DOCX.
5. Дождитесь сообщения об успешной обработке.
6. Задавайте вопросы по активному материалу.
7. Используйте `/summary` для конспекта или `/quiz` для самопроверки.

## Основные файлы

- `main.py` — точка входа и сборка зависимостей;
- `app/bot.py` — обработчики Telegram-команд и сообщений;
- `app/config.py` — загрузка настроек;
- `app/database.py` — работа с SQLite;
- `app/loaders.py` — загрузка PDF, TXT, MD и DOCX;
- `app/splitter.py` — разбиение текста на фрагменты;
- `app/text_utils.py` — нормализация текста и поисковая токенизация;
- `app/search.py` — гибридный поиск по фрагментам;
- `app/ollama_client.py` — запросы к Ollama;
- `app/quiz.py` — состояние и валидация викторины;
- `app/services.py` — основная бизнес-логика.

## Документация исходного кода

Основные модули, классы и функции имеют короткие docstrings. HTML-документация создаётся встроенным `pydoc`.

```bash
python scripts/generate_docs.py
```

Готовые HTML-файлы появятся в `docs/generated/`.

## Ограничения

- Ollama должна быть запущена локально.
- Качество ответов зависит от текстового слоя документа.
- Сканированные PDF без текстового слоя не поддерживаются, потому что OCR отсутствует.
- Сложные или повреждённые формулы из PDF могут извлекаться неточно.
- Большие документы обрабатываются дольше.
- Состояние викторины хранится в памяти процесса и сбрасывается после перезапуска.
